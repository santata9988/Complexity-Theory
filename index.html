1Introduction to Computational Complexity Theory

ความหมาย

Computational Complexity Theory คือสาขาที่ศึกษา “ความยากของปัญหา” โดยดูว่าต้องใช้ทรัพยากร (เวลา, หน่วยความจำ) เท่าใดเมื่อขนาดข้อมูล n เพิ่มขึ้น แล้วจัดปัญหาเป็นกลุ่ม เช่น P, NP

ความสำคัญของการจำแนกความยาก

  • รู้ว่าปัญหาใดแก้ได้เร็วจริง ปัญหาใดแก้ยาก
  • ไม่เสียเวลาหาวิธีที่ดีที่สุด ถ้าปัญหายากมาก ให้เลือกวิธีประมาณคำตอบแทน
  • เป็นฐานของการเข้ารหัสลับ (ใช้ปัญหาที่ยากเป็นเกราะ)

1.1 ความหมายของ Computational Complexity Theory

Computational Complexity Theory หรือทฤษฎีความซับซ้อนในการคำนวณ เป็นสาขาหนึ่งของวิทยาการคอมพิวเตอร์ที่ศึกษาความยากของปัญหาการคำนวณ โดยพิจารณาทรัพยากรที่จำเป็นต้องใช้ในการแก้ปัญหา เช่น เวลาในการประมวลผล (Time Complexity) และหน่วยความจำ (Space Complexity) ทฤษฎีนี้ช่วยให้นักวิทยาการคอมพิวเตอร์เข้าใจว่าปัญหาแต่ละประเภทสามารถแก้ไขได้อย่างมีประสิทธิภาพหรือไม่ เมื่อขนาดของข้อมูลนำเข้าเพิ่มขึ้น

ในการเขียนโปรแกรม เราอาจพบว่ามีอัลกอริทึมหลายแบบที่สามารถแก้ปัญหาเดียวกันได้ แต่แต่ละแบบใช้เวลาและทรัพยากรแตกต่างกัน ตัวอย่างเช่น การค้นหาข้อมูลในรายชื่อที่มีจำนวนไม่มากสามารถทำได้โดยการตรวจสอบทีละรายการ แต่หากมีข้อมูลหลายล้านรายการ วิธีดังกล่าวอาจใช้เวลามาก การศึกษาเรื่องความซับซ้อนจึงช่วยให้สามารถเลือกวิธีแก้ปัญหาที่เหมาะสมกับขนาดข้อมูลและข้อจำกัดของระบบได้

นอกจากนี้ Computational Complexity Theory ยังศึกษาปัญหาที่มีความยากสูง เช่น ปัญหาการจัดเส้นทาง การจัดตารางงาน และการค้นหาคำตอบที่ดีที่สุดจากทางเลือกจำนวนมาก ปัญหาเหล่านี้บางประเภทมีจำนวนทางเลือกเพิ่มขึ้นอย่างรวดเร็วเมื่อข้อมูลเพิ่มขึ้นเพียงเล็กน้อย จึงอาจต้องใช้เวลาในการคำนวณสูงมากหากต้องตรวจสอบทุกทางเลือก

1.2 ความสำคัญของการศึกษาความซับซ้อนในการคำนวณ

การศึกษาทฤษฎีความซับซ้อนมีความสำคัญต่อการออกแบบและพัฒนาซอฟต์แวร์ เพราะช่วยให้ทราบว่าอัลกอริทึมที่เลือกใช้มีประสิทธิภาพเพียงใด และจะยังทำงานได้ดีหรือไม่เมื่อปริมาณข้อมูลเพิ่มขึ้น ตัวอย่างเช่น ระบบฐานข้อมูล ระบบค้นหา ระบบขนส่ง และระบบวางแผนเส้นทาง ล้วนต้องจัดการข้อมูลจำนวนมากและต้องการคำตอบภายในเวลาที่เหมาะสม

อีกประการหนึ่ง ทฤษฎีนี้ช่วยให้นักพัฒนาเข้าใจข้อจำกัดของการหาคำตอบที่ดีที่สุด หากปัญหามีความซับซ้อนสูงมาก การค้นหาคำตอบที่ดีที่สุดทุกกรณีอาจไม่เหมาะสมในทางปฏิบัติ นักพัฒนาอาจเลือกใช้วิธีประมาณคำตอบหรือวิธีค้นหาแบบฮิวริสติกเพื่อให้ได้คำตอบที่ดีภายในเวลาจำกัด

ทฤษฎีนี้ยังมีความสำคัญต่อการเข้ารหัสข้อมูลและความปลอดภัยทางคอมพิวเตอร์ เพราะระบบรักษาความปลอดภัยบางประเภทอาศัยสมมติฐานว่าปัญหาทางคณิตศาสตร์บางอย่างยากต่อการแก้เมื่อไม่มีข้อมูลหรือกุญแจที่จำเป็น อย่างไรก็ตาม ความยากของปัญหาเพียงอย่างเดียวไม่ได้รับประกันความปลอดภัยของระบบทั้งหมด

1.3 ความแตกต่างระหว่าง Algorithm Complexity กับ Computational Complexity

Algorithm Complexity คือการวิเคราะห์ทรัพยากรที่อัลกอริทึมหนึ่ง ๆ ใช้ในการแก้ปัญหา เช่น จำนวนขั้นตอนการทำงานหรือปริมาณหน่วยความจำที่ต้องใช้เมื่อขนาดข้อมูลเพิ่มขึ้น ตัวอย่างเช่น Linear Search มีความซับซ้อนด้านเวลาเป็น O(n) ในกรณีเลวร้ายที่สุด เพราะอาจต้องตรวจสอบข้อมูลครบทุกตำแหน่ง ส่วน Binary Search มีความซับซ้อนเป็น O(log n) เมื่อข้อมูลเรียงลำดับแล้ว

ในทางตรงกันข้าม Computational Complexity เน้นศึกษาความยากของปัญหาในภาพรวม รวมถึงการจำแนกปัญหาออกเป็นกลุ่ม เช่น P, NP, NP-Hard และ NP-Complete ตลอดจนศึกษาความสัมพันธ์ระหว่างกลุ่มปัญหาเหล่านี้

ดังนั้น Algorithm Complexity จึงเน้นว่าอัลกอริทึมที่กำหนดใช้ทรัพยากรมากน้อยเพียงใด ส่วน Computational Complexity เน้นว่าปัญหานั้นมีลักษณะความยากอย่างไร และมีวิธีแก้ที่มีประสิทธิภาพหรือไม่

1.4 ตัวอย่างการประยุกต์ใช้

ตัวอย่างการประยุกต์ใช้ ได้แก่ การออกแบบฐานข้อมูลที่ค้นหาข้อมูลได้รวดเร็ว การสร้างระบบขนส่งที่หาเส้นทางได้เหมาะสม การจัดตารางเรียนโดยลดเวลาว่างของห้องเรียน และการวางแผนการผลิตในโรงงานให้ใช้ทรัพยากรอย่างคุ้มค่า ความรู้เรื่องความซับซ้อนช่วยให้สามารถเลือกอัลกอริทึมที่เหมาะสมกับปัญหาแต่ละประเภทได้

สรุปได้ว่า Computational Complexity Theory เป็นพื้นฐานสำคัญในการทำความเข้าใจข้อจำกัดของการคำนวณ และเป็นจุดเริ่มต้นของการศึกษากลุ่มปัญหา P, NP, NP-Hard และ NP-Complete ในหัวข้อต่อไป

2Polynomial and Exponential Time

Polynomial Time

เวลาไม่เกิน O(nᵏ) เมื่อ k เป็นค่าคงที่ เช่น O(n), O(n²), O(n³) ถือว่าแก้ได้อย่างมีประสิทธิภาพ

Exponential Time

เวลาโตตามเลขชี้กำลังของ n เช่น O(2ⁿ) (ตรวจทุกค่าความจริงของ n ตัวแปร) และ O(n!) (ลองทุกลำดับการเดินทาง) เพิ่ม n ทีละ 1 เวลาเพิ่มเป็นเท่าตัว

2.1 ความหมายของ Time Complexity

Time Complexity หรือความซับซ้อนด้านเวลา หมายถึงการวิเคราะห์จำนวนขั้นตอนที่อัลกอริทึมต้องดำเนินการเมื่อขนาดข้อมูลนำเข้าเพิ่มขึ้น โดยทั่วไปจะใช้ n แทนขนาดข้อมูล และใช้สัญลักษณ์ Big O เพื่อแสดงอัตราการเติบโตของจำนวนขั้นตอน โดยไม่จำเป็นต้องระบุเวลาเป็นวินาทีที่แน่นอน

การวิเคราะห์แบบนี้ทำให้สามารถเปรียบเทียบอัลกอริทึมได้โดยไม่ขึ้นอยู่กับความเร็วของคอมพิวเตอร์เพียงอย่างเดียว ตัวอย่างเช่น โปรแกรมที่ใช้ขั้นตอนประมาณ n² อาจทำงานได้ดีเมื่อข้อมูลมีขนาดเล็ก แต่เมื่อข้อมูลเพิ่มขึ้นมาก จำนวนขั้นตอนจะเพิ่มขึ้นเร็วกว่าวิธีที่ใช้ขั้นตอนประมาณ n log n

2.2 Polynomial Time

Polynomial Time หรือเวลาพหุนาม หมายถึงเวลาการทำงานที่มีขอบเขตเป็นพหุนามของขนาดข้อมูล เช่น O(n), O(n²), O(n³) หรือโดยทั่วไป O(nᵏ) เมื่อ k เป็นค่าคงที่ที่ไม่ขึ้นกับขนาดข้อมูล

อัลกอริทึมที่ใช้เวลาพหุนามมักถือว่ามีประสิทธิภาพในกรอบของทฤษฎีความซับซ้อน แม้ว่าอัลกอริทึมที่เป็นพหุนามบางแบบจะทำงานช้าในทางปฏิบัติหากเลขชี้กำลังหรือค่าคงที่มีขนาดใหญ่ก็ตาม

ตัวอย่างเช่น O(n) หมายถึงจำนวนขั้นตอนเติบโตเป็นสัดส่วนกับขนาดข้อมูล หากมีข้อมูลเพิ่มเป็นสองเท่า จำนวนขั้นตอนโดยประมาณก็เพิ่มเป็นสองเท่า ส่วน O(n²) หมายถึงจำนวนขั้นตอนเติบโตตามกำลังสอง หากข้อมูลเพิ่มเป็นสองเท่า จำนวนขั้นตอนโดยประมาณจะเพิ่มเป็นสี่เท่า

2.3 Exponential Time

Exponential Time หรือเวลาเอ็กซ์โพเนนเชียล หมายถึงเวลาการทำงานที่เพิ่มขึ้นตามฟังก์ชันเลขชี้กำลัง เช่น O(2ⁿ) ซึ่งจำนวนขั้นตอนเพิ่มขึ้นอย่างรวดเร็วเมื่อ n เพิ่มขึ้น

ตัวอย่างเช่น ปัญหาที่มีตัวแปรแบบบูลีน n ตัว สามารถมีการกำหนดค่าความจริงได้ทั้งหมด 2ⁿ รูปแบบ หากใช้อัลกอริทึมตรวจสอบทุกรูปแบบ จำนวนกรณีที่จะต้องตรวจสอบจะเพิ่มขึ้นเป็นสองเท่าทุกครั้งที่เพิ่มตัวแปรหนึ่งตัว

นอกจากนี้ยังมี O(n!) ซึ่งเกี่ยวข้องกับการเรียงลำดับหรือการเลือกเส้นทางจากลำดับที่เป็นไปได้ทั้งหมด โดย n! คือแฟกทอเรียลของ n เช่น 5! = 120 และ 10! = 3,628,800 จำนวนลำดับจะเพิ่มขึ้นอย่างรวดเร็วเมื่อจำนวนสิ่งของเพิ่มขึ้น

ตัวเลขในตารางแสดงค่าของฟังก์ชันโดยประมาณ ไม่ใช่จำนวนขั้นตอนจริงของทุกอัลกอริทึม เนื่องจากอัลกอริทึมแต่ละแบบมีค่าคงที่และรายละเอียดการทำงานแตกต่างกัน

จากตารางจะเห็นว่า O(n) เติบโตช้าที่สุดในกลุ่มที่ยกตัวอย่าง ขณะที่ O(n!) เติบโตเร็วมาก โดยทั่วไป เมื่อ n มีค่ามากพอ ฟังก์ชันแบบเอ็กซ์โพเนนเชียลและแฟกทอเรียลจะทำให้การค้นหาคำตอบทุกกรณีมีต้นทุนสูงมาก

2.5 ตัวอย่างการใช้งาน

การค้นหาข้อมูลแบบ Linear Search เป็นตัวอย่างของ O(n) ส่วนอัลกอริทึมเรียงลำดับแบบ Bubble Sort มีความซับซ้อน O(n²) ในกรณีทั่วไปหรือกรณีเลวร้ายที่สุดตามรูปแบบการใช้งาน ขณะที่การคูณเมทริกซ์แบบพื้นฐานมีความซับซ้อน O(n³) สำหรับเมทริกซ์ขนาด n×n

ส่วน O(2ⁿ) อาจเกิดจากการตรวจสอบชุดย่อยทุกชุด และ O(n!) อาจเกิดจากการตรวจสอบลำดับการเดินทางทุกแบบในปัญหาเส้นทางพนักงานขายด้วยวิธี Brute Force

2.6 สรุป

Polynomial Time มีความสำคัญต่อการจำแนกปัญหาใน Class P ขณะที่เวลาที่เติบโตแบบเอ็กซ์โพเนนเชียลหรือแฟกทอเรียลมักทำให้การแก้ปัญหาขนาดใหญ่มีต้นทุนสูง อย่างไรก็ตาม การที่อัลกอริทึมหนึ่งใช้เวลาเอ็กซ์โพเนนเชียลไม่ได้หมายความว่าปัญหานั้นไม่มีอัลกอริทึมพหุนามเสมอไป เพราะอาจมีวิธีแก้ที่ดีกว่าซึ่งยังไม่ถูกค้นพบหรือยังไม่ได้พิจารณา

3Complexity Class P

ความหมาย

P = กลุ่มปัญหาการตัดสินใจ (ตอบ Yes/No) ที่แก้ได้ด้วยอัลกอริทึมแบบ Deterministic ในเวลาพหุนาม

คุณสมบัติ

  • แก้ได้ในเวลา O(nᵏ) ด้วยเครื่อง Deterministic
  • ถือเป็นปัญหาที่ “แก้ได้จริง” ในทางปฏิบัติ
  • P ⊆ NP

ตัวอย่างปัญหาใน P

  1. มีเส้นทางจาก s ไป t ที่ยาว ≤ k หรือไม่ — Dijkstra แก้ได้ในเวลาพหุนาม
  2. กราฟเชื่อมต่อกันหรือไม่ — BFS/DFS ใช้เวลา O(V+E)
  3. n เป็นจำนวนเฉพาะหรือไม่ — อัลกอริทึม AKS (ปี 2002) เป็นเวลาพหุนาม

3.1 ความหมายของ Class P

Class P หรือ Polynomial-Time Class เป็นกลุ่มของปัญหาการตัดสินใจ (Decision Problems) ที่สามารถแก้ได้ด้วยอัลกอริทึมแบบ Deterministic ในเวลาพหุนาม โดยคำว่า Deterministic หมายถึงการคำนวณที่แต่ละขั้นตอนมีการเลือกการทำงานอย่างแน่นอนภายใต้ข้อมูลนำเข้าและสถานะปัจจุบัน

การแก้ปัญหาในเวลาพหุนามหมายความว่า เวลาการทำงานมีขอบเขตไม่เกิน O(nᵏ) สำหรับค่าคงที่ k บางค่า โดย n คือขนาดข้อมูลนำเข้า ในทางทฤษฎี ปัญหาใน P จึงถือว่าแก้ได้อย่างมีประสิทธิภาพเมื่อพิจารณาการเติบโตของขนาดข้อมูล

อย่างไรก็ตาม การเป็นปัญหาใน P ไม่ได้หมายความว่าโปรแกรมจะต้องทำงานเร็วเสมอไป เพราะอัลกอริทึมที่ใช้ O(n¹⁰⁰) ก็เป็นพหุนามตามนิยาม แม้อาจไม่มีประโยชน์ในทางปฏิบัติสำหรับข้อมูลขนาดใหญ่ ดังนั้นคำว่า “มีประสิทธิภาพ” ในที่นี้เป็นความหมายเชิงทฤษฎีเป็นหลัก

3.2 คุณสมบัติของ Class P

คุณสมบัติสำคัญของ P คือสามารถแก้ปัญหาได้ในเวลาพหุนามโดยใช้แบบจำลองการคำนวณแบบ Deterministic ปัญหาใน P ยังเป็นส่วนหนึ่งของ NP เพราะหากเราสามารถหาคำตอบได้ในเวลาพหุนาม ก็ย่อมสามารถตรวจสอบคำตอบได้ในเวลาพหุนามเช่นกัน

อีกประการหนึ่ง ปัญหาใน P มักมีอัลกอริทึมที่สามารถนำไปใช้กับข้อมูลขนาดใหญ่ได้ง่ายกว่าปัญหาที่ต้องใช้เวลาแบบเอ็กซ์โพเนนเชียล ทั้งนี้ต้องพิจารณาค่าคงที่ ขนาดข้อมูล และข้อจำกัดของระบบร่วมด้วย

3.3 ตัวอย่างปัญหาใน P

ตัวอย่างที่ 1 ปัญหาการเรียงลำดับข้อมูล (Sorting)
การเรียงลำดับข้อมูลสามารถทำได้ด้วยอัลกอริทึม เช่น Merge Sort ซึ่งมีความซับซ้อนด้านเวลา O(n log n) ในกรณีทั่วไปและกรณีเลวร้ายที่สุด เมื่อข้อมูลมีจำนวนเพิ่มขึ้น จำนวนขั้นตอนจะเพิ่มขึ้นตามฟังก์ชันพหุนาม จึงจัดอยู่ใน P

ตัวอย่างที่ 2 ปัญหาการหาเส้นทางสั้นที่สุด
Shortest Path Problem เป็นปัญหาที่ต้องการหาเส้นทางที่มีผลรวมน้ำหนักหรือระยะทางน้อยที่สุดจากจุดเริ่มต้นไปยังจุดหมาย อัลกอริทึม Dijkstra สามารถแก้ปัญหานี้ได้อย่างมีประสิทธิภาพภายใต้เงื่อนไขว่าน้ำหนักเส้นเชื่อมไม่เป็นลบ ส่วนกรณีที่มีน้ำหนักติดลบสามารถใช้วิธีอื่น เช่น Bellman–Ford ภายใต้เงื่อนไขที่เหมาะสม ปัญหาเหล่านี้มีอัลกอริทึมพหุนามสำหรับรูปแบบมาตรฐาน จึงเป็นตัวอย่างของปัญหาใน P

ตัวอย่างที่ 3 ปัญหาการเชื่อมต่อของกราฟ (Graph Connectivity)
ปัญหานี้ต้องการตรวจสอบว่าจุดยอดในกราฟสามารถเดินทางถึงกันได้หรือไม่ โดยสามารถใช้ Breadth-First Search หรือ Depth-First Search สำรวจจุดยอดและเส้นเชื่อมได้ในเวลา O(V+E) เมื่อ V คือจำนวนจุดยอดและ E คือจำนวนเส้นเชื่อม ดังนั้นปัญหาการตรวจสอบการเชื่อมต่อจึงอยู่ใน P

ตัวอย่างที่ 4 ปัญหาการหาตัวหารร่วมมาก
การหาตัวหารร่วมมากหรือ Greatest Common Divisor สามารถใช้ Euclidean Algorithm ซึ่งทำงานได้ในเวลาพหุนามตามความยาวของข้อมูลตัวเลข จึงเป็นตัวอย่างของการคำนวณที่มีประสิทธิภาพ

3.4 ความสำคัญของ P ในการแก้ปัญหา

Class P มีบทบาทสำคัญในการพัฒนาซอฟต์แวร์ เนื่องจากเป็นกลุ่มปัญหาที่เราทราบว่ามีวิธีแก้ในเวลาพหุนาม ตัวอย่างการใช้งานได้แก่ การจัดเรียงข้อมูล การค้นหาเส้นทาง การตรวจสอบการเชื่อมต่อเครือข่าย และการคำนวณพื้นฐานทางคณิตศาสตร์

การทราบว่าปัญหาอยู่ใน P ยังช่วยให้ผู้พัฒนามั่นใจได้ว่ามีอัลกอริทึมที่มีขอบเขตเวลาการทำงานแบบพหุนาม แม้ยังต้องเลือกวิธีที่เหมาะสมกับข้อมูลจริงอีกครั้งก็ตาม

3.5 สรุป

Class P ประกอบด้วยปัญหาการตัดสินใจที่สามารถแก้ได้ในเวลาพหุนามด้วยอัลกอริทึมแบบ Deterministic ปัญหาในกลุ่มนี้มีความสำคัญต่อการพัฒนาระบบที่ต้องทำงานกับข้อมูลจำนวนมาก ตัวอย่างที่สำคัญ ได้แก่ การเรียงลำดับข้อมูล การหาเส้นทางสั้นที่สุด และการตรวจสอบการเชื่อมต่อของกราฟ

4Complexity Class NP

ความหมาย

NP = ปัญหาการตัดสินใจที่ ถ้าคำตอบเป็น Yes จะมี Certificate (หลักฐานคำตอบ) ที่ตรวจสอบได้ใน เวลาพหุนาม (NP = Nondeterministic Polynomial ไม่ได้แปลว่า “ไม่ใช่พหุนาม”)

Polynomial-Time Verification

ข้อมูลนำเข้า x + Certificate c → ตัวตรวจสอบ V(x, c) → ยอมรับ/ปฏิเสธ ใน poly(|x|)

ตัวอย่างปัญหาใน NP

ปัญหา Certificate วิธีตรวจ
SAT ค่าความจริงของตัวแปร แทนค่าในสูตร
Hamiltonian Cycle ลำดับจุดยอดของวงจร ครบทุกจุดไม่ซ้ำ และมีเส้นเชื่อมทุกคู่
Vertex Cover (≤ k) ชุดจุดยอด ขนาด ≤ k และทุกเส้นมีปลายในชุด

ตรวจง่าย ≠ หาคำตอบง่าย

ขยายความ (เนื้อหาละเอียด)

4.1 ความหมายของ Class NP

Class NP ย่อมาจาก Nondeterministic Polynomial Time เป็นกลุ่มของปัญหาการตัดสินใจที่คำตอบแบบ Yes สามารถตรวจสอบความถูกต้องได้ในเวลาพหุนาม เมื่อได้รับหลักฐานหรือคำตอบประกอบที่เหมาะสม ซึ่งเรียกว่า Certificate

แนวคิดสำคัญคือ NP ไม่ได้หมายความว่าปัญหานั้นแก้ยากเสมอไป และไม่ได้หมายความว่าไม่สามารถแก้คำตอบได้ในเวลาพหุนาม แต่เป็นการอธิบายคุณสมบัติของการตรวจสอบคำตอบ โดยปัญหาใน P ทุกปัญหาก็อยู่ใน NP ด้วย เพราะหากแก้ปัญหาได้ในเวลาพหุนาม ก็สามารถตรวจสอบคำตอบได้ในเวลาพหุนามเช่นกัน

4.2 Polynomial-Time Verification

Polynomial-Time Verification หมายถึงการตรวจสอบว่า Certificate ที่ได้รับเป็นหลักฐานของคำตอบแบบ Yes จริงหรือไม่ โดยใช้เวลาไม่เกินพหุนามตามขนาดข้อมูลนำเข้า

ตัวอย่างเช่น สมมติว่ามีกราฟหนึ่งกราฟและต้องการตรวจสอบว่ามีเส้นทางที่ผ่านจุดยอดทุกจุดเพียงครั้งเดียวและกลับมายังจุดเริ่มต้นหรือไม่ หากมีผู้เสนอเส้นทางมาให้ เราสามารถตรวจสอบได้ว่าเส้นทางใช้เส้นเชื่อมที่มีอยู่จริงหรือไม่ ผ่านจุดยอดครบทุกจุดหรือไม่ และกลับมายังจุดเริ่มต้นหรือไม่ การตรวจสอบนี้ทำได้โดยไม่จำเป็นต้องค้นหาเส้นทางทุกแบบ

4.3 ความหมายของ Certificate

Certificate คือข้อมูลที่ใช้เป็นหลักฐานเพื่อแสดงว่าคำตอบของปัญหาเป็น Yes ตัวอย่างเช่น ในปัญหา SAT ซึ่งถามว่าสูตรตรรกศาสตร์มีการกำหนดค่าความจริงที่ทำให้สูตรเป็นจริงหรือไม่ Certificate อาจเป็นชุดค่าความจริงของตัวแปรแต่ละตัว

หากมีสูตร F = (x₁ ∨ x₂) ∧ (¬x₁ ∨ x₃) และกำหนด x₁ = True, x₂ = False, x₃ = True เราสามารถแทนค่าลงในสูตรเพื่อตรวจสอบได้ว่าแต่ละส่วนเป็นจริงและสูตรทั้งหมดเป็นจริงหรือไม่ กระบวนการตรวจสอบนี้ทำได้รวดเร็วเมื่อเทียบกับการค้นหาค่าความจริงทุกแบบในกรณีที่มีตัวแปรจำนวนมาก

4.4 ตัวอย่างปัญหาใน NP

ตัวอย่างที่ 1 SAT
SAT ถามว่าสูตรตรรกศาสตร์แบบบูลีนมีการกำหนดค่าความจริงให้ตัวแปรจนทำให้สูตรทั้งหมดเป็นจริงได้หรือไม่ หากมีการกำหนดค่าตัวแปรมาให้ เราสามารถแทนค่าและตรวจสอบสูตรได้ในเวลาพหุนาม ดังนั้น SAT จึงอยู่ใน NP

ตัวอย่างที่ 2 Hamiltonian Cycle
ปัญหานี้ถามว่ากราฟมีวงจรที่ผ่านจุดยอดทุกจุดเพียงครั้งเดียวก่อนกลับมายังจุดเริ่มต้นหรือไม่ Certificate คือรายการลำดับจุดยอดของวงจร ซึ่งสามารถตรวจสอบการใช้เส้นเชื่อมและการผ่านจุดยอดได้ในเวลาพหุนาม

ตัวอย่างที่ 3 Vertex Cover
ปัญหานี้ถามว่ากราฟมีชุดจุดยอดขนาดไม่เกิน k ที่ครอบคลุมเส้นเชื่อมทุกเส้นหรือไม่ Certificate คือชุดจุดยอดที่เสนอมา จากนั้นตรวจสอบว่าแต่ละเส้นเชื่อมมีปลายอย่างน้อยหนึ่งด้านอยู่ในชุดดังกล่าวหรือไม่ การตรวจสอบสามารถทำได้ในเวลาพหุนาม

ตัวอย่างที่ 4 Traveling Salesman Problem แบบ Decision
ปัญหานี้ถามว่ามีเส้นทางแบบวงรอบที่ผ่านทุกเมืองและมีระยะทางรวมไม่เกินค่าที่กำหนดหรือไม่ หากมีการเสนอเส้นทางมาให้ เราสามารถตรวจสอบว่าเดินทางผ่านเมืองครบทุกเมืองและผลรวมระยะทางไม่เกินขอบเขตหรือไม่ในเวลาพหุนาม

4.5 ความแตกต่างระหว่างการแก้ปัญหากับการตรวจสอบคำตอบ

การตรวจสอบคำตอบอาจง่ายกว่าการค้นหาคำตอบมาก ตัวอย่างเช่น การตรวจสอบว่าชุดจุดยอดที่กำหนดเป็น Vertex Cover หรือไม่สามารถทำได้โดยตรวจสอบเส้นเชื่อมทุกเส้น แต่การค้นหาว่ามี Vertex Cover ขนาดไม่เกิน k อยู่หรือไม่ อาจต้องพิจารณาชุดจุดยอดหลายชุด

นี่คือเหตุผลสำคัญที่ทำให้ Class NP มีบทบาทในทฤษฎีความซับซ้อน เพราะมีปัญหาหลายประเภทที่เราสามารถตรวจสอบคำตอบได้รวดเร็ว แต่ยังไม่ทราบวิธีหาคำตอบที่มีประสิทธิภาพในทุกกรณี

4.6 สรุป

Class NP ประกอบด้วยปัญหาการตัดสินใจที่คำตอบแบบ Yes มี Certificate ซึ่งสามารถตรวจสอบได้ในเวลาพหุนาม การอยู่ใน NP ไม่ได้หมายความว่าปัญหานั้นต้องแก้ยาก และยังไม่มีข้อพิสูจน์ว่า P เท่ากับ NP หรือไม่ ปัญหา SAT, Hamiltonian Cycle, Vertex Cover และ Traveling Salesman Problem แบบ Decision เป็นตัวอย่างสำคัญของปัญหาใน NP

5Relationship Between P and NP

ความสัมพันธ์

P ⊆ NP — ถ้าแก้ได้ในเวลาพหุนาม ก็ตรวจคำตอบได้ในเวลาพหุนามด้วย

ปัญหา P vs NP

ถามว่า P = NP หรือไม่ คือ ปัญหาที่ตรวจคำตอบได้เร็วทุกข้อ แก้ได้เร็วด้วยหรือไม่

  • ถ้า P = NP: ทุกปัญหาใน NP แก้ได้เร็ว กระทบการเข้ารหัสและการหาคำตอบที่ดีที่สุด
  • ถ้า P ≠ NP: มีปัญหาที่ตรวจเร็วแต่แก้เร็วไม่ได้

ทำไมยังเป็นปัญหาเปิด

ยังไม่มีใครพิสูจน์ได้ทั้งสองทาง (ไม่มีอัลกอริทึมพหุนามให้ปัญหา NP-Complete และไม่มีข้อพิสูจน์ว่าทำไม่ได้) เป็นหนึ่งใน Millennium Prize Problems ของ Clay Institute

แผนภาพ P ⊆ NP (ถ้า P = NP สองวงจะทับกัน)

ขยายความ (เนื้อหาละเอียด)

5.1 ความสัมพันธ์ระหว่าง P และ NP

Class P และ Class NP เป็นกลุ่มความซับซ้อนที่มีความสัมพันธ์กันอย่างใกล้ชิด P ประกอบด้วยปัญหาการตัดสินใจที่สามารถแก้ได้ในเวลาพหุนาม ส่วน NP ประกอบด้วยปัญหาที่คำตอบแบบ Yes สามารถตรวจสอบได้ในเวลาพหุนาม

เนื่องจากหากเราสามารถแก้ปัญหาได้ในเวลาพหุนาม เราก็สามารถนำคำตอบที่ได้มาตรวจสอบได้ในเวลาพหุนามเช่นกัน จึงสรุปได้ว่า

P ⊆ NP

ความสัมพันธ์นี้หมายความว่าทุกปัญหาใน P อยู่ใน NP แต่ไม่ได้ยืนยันว่าทุกปัญหาใน NP จะอยู่ใน P ด้วยหรือไม่

5.2 ปัญหา P versus NP

P versus NP หรือปัญหา P vs NP เป็นหนึ่งในปัญหาสำคัญของวิทยาการคอมพิวเตอร์เชิงทฤษฎี โดยตั้งคำถามว่า ปัญหาทุกปัญหาที่สามารถตรวจสอบคำตอบแบบ Yes ได้ในเวลาพหุนาม จะสามารถแก้คำตอบได้ในเวลาพหุนามด้วยหรือไม่ กล่าวอีกนัยหนึ่งคือ P เท่ากับ NP หรือไม่

หากพิสูจน์ได้ว่า P = NP จะหมายความว่าปัญหาทุกปัญหาใน NP สามารถแก้ได้ในเวลาพหุนาม ซึ่งอาจมีผลอย่างมากต่อการแก้ปัญหาการวางแผน การหาคำตอบที่เหมาะสมที่สุด และการพิสูจน์ทางคณิตศาสตร์บางประเภท อย่างไรก็ตาม ไม่ได้หมายความว่าทุกปัญหาจะง่ายในทางปฏิบัติ เพราะอัลกอริทึมพหุนามอาจมีค่าคงที่สูงหรือมีเลขชี้กำลังขนาดใหญ่

หากพิสูจน์ได้ว่า P ≠ NP จะหมายความว่ามีปัญหาบางประเภทที่สามารถตรวจสอบคำตอบได้ในเวลาพหุนาม แต่ไม่สามารถแก้ได้ในเวลาพหุนามด้วยแบบจำลองการคำนวณที่กำหนด

จนถึงปัจจุบัน ปัญหา P vs NP ยังเป็นปัญหาเปิด กล่าวคือยังไม่มีข้อพิสูจน์ที่ได้รับการยอมรับทั่วไปว่าสองกลุ่มนี้เท่ากันหรือแตกต่างกัน

5.3 ความสำคัญของปัญหา P vs NP

ปัญหานี้มีความสำคัญเพราะเชื่อมโยงกับการค้นหาคำตอบที่ดีที่สุดจากทางเลือกจำนวนมาก เช่น การจัดเส้นทางพนักงานขาย การจัดตารางการผลิต และการวางแผนการขนส่ง หากปัญหาสำคัญใน NP สามารถแก้ได้ในเวลาพหุนาม ก็อาจช่วยเพิ่มประสิทธิภาพการแก้ปัญหาเหล่านี้ได้อย่างมาก

อย่างไรก็ตาม การมีอัลกอริทึมที่ตรวจสอบคำตอบได้รวดเร็วไม่ได้รับประกันว่าจะสามารถค้นหาคำตอบได้รวดเร็วเช่นกัน การตรวจสอบเส้นทางที่กำหนดมาให้อาจทำได้ง่าย แต่การค้นหาเส้นทางที่เหมาะสมจากเส้นทางที่เป็นไปได้จำนวนมหาศาลอาจทำได้ยากกว่า

5.4 แผนภาพแสดงความสัมพันธ์

ภาพนี้แสดงความสัมพันธ์ P ⊆ NP ที่ทราบแน่นอน โดยยังไม่ทราบว่า P = NP หรือ P เป็นส่วนย่อยอย่างแท้จริงของ NP

5.5 ความเกี่ยวข้องกับ NP-Complete

ปัญหา NP-Complete เป็นปัญหาที่อยู่ใน NP และเป็น NP-Hard ด้วย ปัญหากลุ่มนี้มีบทบาทสำคัญต่อ P vs NP เพราะหากสามารถแก้ปัญหา NP-Complete ปัญหาใดปัญหาหนึ่งได้ในเวลาพหุนาม จะสามารถใช้ Polynomial-Time Reduction แก้ปัญหาอื่น ๆ ใน NP ได้ในเวลาพหุนามเช่นกัน ดังนั้นจะได้ P = NP

ในทางกลับกัน หากพิสูจน์ได้ว่าปัญหา NP-Complete ปัญหาใดปัญหาหนึ่งไม่สามารถแก้ได้ในเวลาพหุนาม ก็จะเป็นหลักฐานว่า P ≠ NP ภายใต้กรอบนิยามมาตรฐาน

5.6 สรุป

ความสัมพันธ์ที่ทราบแน่นอนคือ P ⊆ NP แต่คำถามว่า P = NP หรือไม่ยังไม่มีคำตอบที่เป็นที่ยอมรับทั่วไป ปัญหานี้มีความสำคัญต่อการทำความเข้าใจข้อจำกัดของการคำนวณ และเชื่อมโยงกับแนวคิด NP-Hard และ NP-Complete ซึ่งจะอธิบายในหัวข้อต่อไป

ขยายความ (เนื้อหาละเอียด)

6.1 ความหมายของ NP-Hard

NP-Hard เป็นคุณสมบัติของปัญหาที่มีความยากอย่างน้อยเทียบเท่ากับทุกปัญหาใน NP ภายใต้ Polynomial-Time Reduction กล่าวคือ หากมีอัลกอริทึมที่แก้ปัญหา NP-Hard ได้ในเวลาพหุนาม และการลดรูปที่เกี่ยวข้องเป็นไปตามเงื่อนไข ก็จะสามารถนำวิธีดังกล่าวไปแก้ปัญหาทุกปัญหาใน NP ได้ในเวลาพหุนามด้วย

แนวคิดนี้ไม่ได้หมายความว่าปัญหา NP-Hard ทุกปัญหาจะมีคำตอบที่ตรวจสอบได้ในเวลาพหุนาม และไม่ได้หมายความว่าทุกปัญหา NP-Hard เป็นปัญหาใน NP เพราะนิยามของ NP-Hard ไม่ได้กำหนดให้ปัญหาต้องอยู่ใน NP

6.2 คุณสมบัติของ NP-Hard

คุณสมบัติสำคัญคือ ปัญหาใน NP ทุกปัญหาสามารถลดรูปมายังปัญหา NP-Hard ที่กำหนดได้ในเวลาพหุนาม การลดรูปนี้ใช้แสดงว่าปัญหาปลายทางมีความยากอย่างน้อยเท่ากับปัญหาต้นทาง

ปัญหา NP-Hard อาจเป็นปัญหาการตัดสินใจ ปัญหาการหาคำตอบที่เหมาะสมที่สุด หรือปัญหาในรูปแบบอื่นก็ได้ ขึ้นอยู่กับนิยามของปัญหาและการเปรียบเทียบความยากที่ใช้

ตัวอย่างเช่น Traveling Salesman Problem แบบ Optimization ต้องการหาเส้นทางที่มีระยะทางรวมน้อยที่สุด ไม่ใช่เพียงตอบ Yes หรือ No ปัญหา Optimization รุ่นมาตรฐานนี้เป็น NP-Hard ขณะที่รุ่น Decision ซึ่งถามว่ามีเส้นทางที่มีระยะทางไม่เกิน B หรือไม่ เป็น NP-Complete ภายใต้เงื่อนไขมาตรฐาน

6.3 ตัวอย่างปัญหา NP-Hard

ตัวอย่างที่ 1 Traveling Salesman Problem แบบ Optimization
ปัญหานี้ต้องการหาเส้นทางที่ผ่านเมืองแต่ละเมืองและกลับมายังเมืองเริ่มต้น โดยทำให้ระยะทางรวมต่ำที่สุด การตรวจสอบเส้นทางที่กำหนดมาให้ทำได้รวดเร็ว แต่การหาคำตอบที่ดีที่สุดในทุกกรณีเป็นปัญหาที่มีความยากสูง และรุ่น Optimization เป็น NP-Hard

ตัวอย่างที่ 2 ปัญหา Set Cover แบบ Optimization
ปัญหานี้กำหนดจักรวาลขององค์ประกอบและชุดย่อยหลายชุด โดยต้องการเลือกชุดย่อยจำนวนต่ำที่สุดให้ครอบคลุมองค์ประกอบทั้งหมด รุ่น Optimization ของปัญหานี้เป็น NP-Hard ส่วนรุ่น Decision ที่ถามว่าสามารถครอบคลุมทั้งหมดด้วยชุดย่อยไม่เกิน k ชุดได้หรือไม่ เป็นปัญหา NP-Complete ในรูปแบบมาตรฐาน

ตัวอย่างที่ 3 ปัญหา Scheduling แบบ Optimization
ปัญหาการจัดตารางงานบางประเภทต้องการจัดสรรงานให้เครื่องจักรหรือทรัพยากรโดยลดเวลารวม ลดเวลาที่งานเสร็จช้าที่สุด หรือเพิ่มประสิทธิภาพตามเป้าหมายที่กำหนด ปัญหาการจัดตารางงานหลายรูปแบบเป็น NP-Hard โดยความยากขึ้นอยู่กับข้อจำกัดและนิยามของปัญหา

6.4 ความแตกต่างระหว่าง NP กับ NP-Hard

NP เน้นคุณสมบัติการตรวจสอบคำตอบแบบ Yes ด้วย Certificate ในเวลาพหุนาม ขณะที่ NP-Hard เน้นความยากของปัญหาเมื่อเปรียบเทียบกับทุกปัญหาใน NP

ปัญหาใน NP-Hard ไม่จำเป็นต้องอยู่ใน NP และอาจไม่มี Certificate ที่ตรวจสอบได้ในเวลาพหุนามตามนิยามมาตรฐาน ดังนั้นจึงไม่ควรกล่าวว่าปัญหา NP-Hard ทุกปัญหาสามารถตรวจสอบคำตอบได้รวดเร็ว

6.5 ความสำคัญของ NP-Hard

การจำแนกปัญหาเป็น NP-Hard ช่วยให้นักพัฒนาทราบว่าการค้นหาคำตอบที่ดีที่สุดอาจต้องใช้ทรัพยากรสูง จึงอาจต้องใช้ Approximation Algorithms, Heuristics หรือ Metaheuristics เพื่อค้นหาคำตอบที่ดีภายในเวลาที่จำกัด

ตัวอย่างเช่น ระบบขนส่งสินค้าอาจมีเส้นทางที่เป็นไปได้จำนวนมาก หากต้องหาคำตอบที่ดีที่สุดทุกกรณีอาจใช้เวลานาน การใช้วิธีประมาณคำตอบจึงช่วยให้สามารถวางแผนได้จริงมากขึ้น แม้จะไม่รับประกันว่าคำตอบที่ได้ดีที่สุดเสมอไป

6.6 สรุป

NP-Hard เป็นการจำแนกความยากของปัญหา โดยทุกปัญหาใน NP สามารถลดรูปมายังปัญหา NP-Hard ได้ในเวลาพหุนาม ปัญหา NP-Hard ไม่จำเป็นต้องอยู่ใน NP ตัวอย่างได้แก่ Traveling Salesman Problem แบบ Optimization, Set Cover แบบ Optimization และปัญหาการจัดตารางงานหลายรูปแบบ

7.1 ความหมายของ NP-Complete

NP-Complete เป็นกลุ่มของปัญหาการตัดสินใจที่มีคุณสมบัติสำคัญสองประการ ประการแรก ปัญหาต้องอยู่ใน NP หมายความว่าคำตอบแบบ Yes สามารถตรวจสอบได้ในเวลาพหุนาม ประการที่สอง ปัญหาต้องเป็น NP-Hard หมายความว่าทุกปัญหาใน NP สามารถลดรูปมายังปัญหานั้นได้ในเวลาพหุนาม

ดังนั้น หากต้องการพิสูจน์ว่าปัญหาใดเป็น NP-Complete จะต้องพิสูจน์ทั้งสองส่วน ไม่ใช่เพียงแสดงว่าปัญหานั้นแก้ยากหรือมีจำนวนทางเลือกมากเท่านั้น

7.2 เงื่อนไขในการพิสูจน์ NP-Completeness

การพิสูจน์โดยทั่วไปประกอบด้วยขั้นตอนต่อไปนี้

ขั้นแรก แสดงว่าปัญหาที่ต้องการพิสูจน์อยู่ใน NP โดยอธิบายว่า Certificate คืออะไร และแสดงวิธีตรวจสอบ Certificate ในเวลาพหุนาม

ขั้นที่สอง เลือกปัญหาที่ทราบอยู่แล้วว่าเป็น NP-Complete จากนั้นสร้าง Polynomial-Time Reduction จากปัญหานั้นมายังปัญหาใหม่ที่ต้องการพิสูจน์

ขั้นที่สาม แสดงว่าการแปลงข้อมูลนำเข้าทำได้ในเวลาพหุนาม และคำตอบของปัญหาต้นทางเป็น Yes ก็ต่อเมื่อคำตอบของปัญหาปลายทางเป็น Yes

หากพิสูจน์ได้ครบทั้งสามส่วน ก็สามารถสรุปได้ว่าปัญหาใหม่เป็น NP-Hard และเมื่อรวมกับการอยู่ใน NP จะได้ว่าปัญหานั้นเป็น NP-Complete

7.3 ตัวอย่างปัญหา NP-Complete

ตัวอย่างที่ 1 SAT
SAT ถามว่าสูตรตรรกศาสตร์แบบบูลีนมีการกำหนดค่าความจริงที่ทำให้สูตรทั้งหมดเป็นจริงได้หรือไม่ ปัญหานี้อยู่ใน NP เพราะตรวจสอบชุดค่าความจริงที่เสนอมาได้ในเวลาพหุนาม และเป็นปัญหา NP-Complete ตามทฤษฎีบทของ Cook–Levin

ตัวอย่างที่ 2 3-SAT

ปัญหานี้ถามว่ามีชุดจุดยอดขนาดไม่เกิน k ที่ครอบคลุมเส้นเชื่อมทุกเส้นในกราฟหรือไม่ การตรวจสอบชุดจุดยอดที่เสนอมาให้ทำได้ในเวลาพหุนาม และปัญหา Vertex Cover แบบ Decision เป็น NP-Complete

ปัญหานี้ถามว่ากราฟมีวงจรที่ผ่านจุดยอดทุกจุดเพียงครั้งเดียวก่อนกลับไปยังจุดเริ่มต้นหรือไม่ สามารถตรวจสอบวงจรที่เสนอมาให้ได้ในเวลาพหุนาม และปัญหานี้เป็น NP-Complete สำหรับกราฟทั่วไป

7.4 ความแตกต่างระหว่าง NP-Hard กับ NP-Complete

ความแตกต่างที่สำคัญคือ NP-Complete ต้องอยู่ใน NP และต้องเป็น NP-Hard ด้วย ส่วน NP-Hard ต้องมีความยากอย่างน้อยเทียบเท่าทุกปัญหาใน NP แต่ไม่จำเป็นต้องอยู่ใน NP

กล่าวอีกนัยหนึ่ง ปัญหา NP-Complete เป็นส่วนหนึ่งของกลุ่ม NP-Hard แต่ปัญหา NP-Hard บางปัญหาอาจไม่ใช่ NP-Complete เพราะอาจเป็นปัญหา Optimization หรือมีลักษณะอื่นที่ไม่อยู่ใน NP ตามนิยามมาตรฐาน

หากพบอัลกอริทึมพหุนามสำหรับปัญหา NP-Complete ปัญหานั้นจะทำให้สามารถแก้ทุกปัญหาใน NP ในเวลาพหุนามได้ผ่านการลดรูป ดังนั้นจึงจะได้ P = NP

7.5 สรุป

NP-Complete เป็นกลุ่มปัญหาที่มีความสำคัญมากในการศึกษาความซับซ้อน เพราะเป็นปัญหาที่อยู่ใน NP และเป็น NP-Hard ด้วย การพิสูจน์ต้องแสดงทั้งการตรวจสอบคำตอบในเวลาพหุนามและการลดรูปจากปัญหา NP-Complete ที่ทราบอยู่แล้ว ตัวอย่างสำคัญ ได้แก่ SAT, 3-SAT, Vertex Cover และ Hamiltonian Cycle

  • ถ้า B แก้ได้เร็ว ก็แก้ A ได้เร็ว (ผ่าน f)
  • ถ้า A ยากและ A ≤ₚ B แล้ว B ยากด้วย

เช่น เส้นทาง A–B–C: S = {A, C} (k = 2) ↔ V∖S = {B} ขนาด 3 − 2 = 1 ครอบทั้งสองเส้น → Yes ทั้งคู่

8.1 ความหมายของ Polynomial-Time Reduction

Polynomial-Time Reduction หรือการลดรูปปัญหาในเวลาพหุนาม เป็นเทคนิคสำคัญใน Computational Complexity Theory ใช้แปลงปัญหาหนึ่งให้เป็นอีกปัญหาหนึ่ง โดยต้องใช้เวลาในการแปลงไม่เกินเวลาพหุนาม และต้องรักษาความถูกต้องของคำตอบตามเงื่อนไขของการลดรูป

แนวคิดนี้ช่วยให้นักวิจัยเปรียบเทียบความยากของปัญหาได้ หากปัญหา A สามารถลดรูปไปเป็นปัญหา B ในเวลาพหุนาม เราเขียนได้ว่า

A ≤ₚ B

ความหมายคือ หากเรามีวิธีแก้ปัญหา B ที่มีประสิทธิภาพ เราสามารถนำวิธีนั้นมาใช้แก้ปัญหา A ได้ โดยเริ่มจากแปลงข้อมูลของ A ให้เป็นข้อมูลของ B แล้วนำคำตอบของ B กลับมาใช้ตอบ A

การลดรูปไม่ได้หมายถึงการทำให้ปัญหาง่ายลงเสมอไป แต่เป็นการแสดงว่าปัญหาหนึ่งสามารถจำลองหรือแปลงให้อยู่ในรูปของอีกปัญหาหนึ่งได้

8.2 ความสำคัญของการลดรูป

Polynomial-Time Reduction มีความสำคัญอย่างยิ่งต่อการพิสูจน์ว่าโจทย์เป็น NP-Hard หรือ NP-Complete เพราะเราไม่จำเป็นต้องพิสูจน์ความยากของปัญหาใหม่ทั้งหมดตั้งแต่ต้น หากมีปัญหาที่ทราบอยู่แล้วว่าเป็น NP-Complete เราสามารถใช้ปัญหานั้นเป็นต้นทางในการลดรูปไปยังปัญหาใหม่ได้

อย่างไรก็ตาม ต้องระวังทิศทางของการลดรูป หากต้องการพิสูจน์ว่าปัญหา B เป็น NP-Hard เราต้องลดรูปจากปัญหา A ที่ทราบแล้วว่าเป็น NP-Hard หรือ NP-Complete มายัง B ไม่ใช่ลดรูปจาก B ไปยัง A เพราะทิศทางดังกล่าวเพียงอย่างเดียวไม่ได้แสดงว่าปัญหา B ยากเทียบเท่ากับ A

นอกจากนี้ การลดรูปต้องรักษาคำตอบให้ถูกต้อง กล่าวคือ อินสแตนซ์ของปัญหาต้นทางต้องตอบ Yes ก็ต่อเมื่ออินสแตนซ์ที่แปลงแล้วของปัญหาปลายทางตอบ Yes เช่นเดียวกัน

8.3 ตัวอย่างการลดรูปจาก Vertex Cover ไปยัง Independent Set

พิจารณากราฟ G = (V, E) ซึ่งประกอบด้วยเซตจุดยอด V และเซตเส้นเชื่อม E

Vertex Cover คือเซตของจุดยอดที่มีจุดยอดอย่างน้อยหนึ่งด้านของทุกเส้นเชื่อมอยู่ในเซตนั้น ส่วน Independent Set คือเซตของจุดยอดที่ไม่มีเส้นเชื่อมใดเชื่อมระหว่างจุดยอดสองจุดภายในเซต

ข้อสังเกตสำคัญคือ เซต C เป็น Vertex Cover ก็ต่อเมื่อส่วนเติมเต็ม V∖C เป็น Independent Set

หากกราฟมีจุดยอดทั้งหมด n จุด และต้องการตรวจสอบว่ามี Vertex Cover ขนาดไม่เกิน k หรือไม่ เราสามารถแปลงเป็นคำถามว่า มี Independent Set ขนาดอย่างน้อย n−k หรือไม่ เพราะจำนวนจุดยอดที่อยู่นอก Vertex Cover จะต้องไม่เชื่อมต่อกันด้วยเส้นเชื่อมภายในเซตนั้น

ตัวอย่างเช่น สมมติกราฟมีจุดยอด V = {A, B, C} และเส้นเชื่อม E = {(A,B), (B,C)} หากเลือก Vertex Cover เป็น {B} จะครอบคลุมเส้นเชื่อมทั้งสองเส้นได้ ส่วนจุดยอดที่เหลือคือ {A, C} ซึ่งไม่มีเส้นเชื่อมระหว่างกัน จึงเป็น Independent Set

ดังนั้น หากถามว่ากราฟนี้มี Vertex Cover ขนาดไม่เกิน 1 หรือไม่ คำตอบคือ Yes และคำถามที่สอดคล้องกันคือ มี Independent Set ขนาดอย่างน้อย 3−1 = 2 หรือไม่ ซึ่งคำตอบก็เป็น Yes เช่นกัน

การแปลงนี้ทำได้ในเวลาพหุนาม เพราะเพียงคำนวณจำนวนจุดยอดและเปลี่ยนค่าเกณฑ์จาก k เป็น n−k โดยใช้กราฟเดิม จึงเป็นตัวอย่างของการลดรูปในเวลาพหุนาม

8.4 การใช้ Reduction เพื่อพิสูจน์ NP-Completeness

หากต้องการพิสูจน์ว่า Independent Set เป็น NP-Complete สามารถเริ่มจากปัญหา Vertex Cover ซึ่งทราบอยู่แล้วว่าเป็น NP-Complete แล้วใช้ความสัมพันธ์ระหว่างสองปัญหามาสร้างการลดรูปในเวลาพหุนาม เมื่อแสดงว่าการแปลงรักษาคำตอบ และ Independent Set อยู่ใน NP เพราะตรวจสอบชุดจุดยอดที่เสนอมาได้ในเวลาพหุนาม ก็สามารถสรุปได้ว่า Independent Set เป็น NP-Complete

ตัวอย่างการลดรูปจาก 3-SAT ไปยัง Hamiltonian Cycle ก็เป็นเทคนิคมาตรฐานที่ใช้สร้างหลักฐานว่าปัญหา Hamiltonian Cycle เป็น NP-Hard และเมื่อแสดงเพิ่มเติมว่าปัญหานี้อยู่ใน NP ก็จะสรุปความเป็น NP-Complete ได้

8.5 ข้อควรระวังในการลดรูป

การลดรูปต้องมีหลักฐานรองรับทั้งเรื่องเวลาที่ใช้แปลงข้อมูลและความสัมพันธ์ของคำตอบ การยกตัวอย่างบางกรณีที่ให้คำตอบเหมือนกันยังไม่เพียงพอที่จะพิสูจน์ว่าการลดรูปถูกต้องสำหรับทุกอินสแตนซ์

นอกจากนี้ ต้องใช้ปัญหาต้นทางที่ทราบสถานะความซับซ้อนอย่างถูกต้อง และแสดงว่าการแปลงสามารถดำเนินการได้กับข้อมูลทุกกรณีภายใต้เงื่อนไขของปัญหา

8.6 สรุป

Polynomial-Time Reduction เป็นเครื่องมือสำคัญในการเปรียบเทียบความยากของปัญหาและพิสูจน์ NP-Hard หรือ NP-Complete การลดรูปที่ถูกต้องต้องแปลงข้อมูลได้ในเวลาพหุนามและรักษาคำตอบตามนิยาม ตัวอย่างความสัมพันธ์ระหว่าง Vertex Cover และ Independent Set แสดงให้เห็นว่าปัญหาที่มีลักษณะแตกต่างกันสามารถเชื่อมโยงกันผ่านการแปลงที่ถูกต้องได้

ปัญหา NP-Complete เป็นกลุ่มปัญหาที่สำคัญ เพราะเป็นปัญหาที่อยู่ใน NP และมีความยากเทียบเท่ากับปัญหาทุกปัญหาใน NP ภายใต้ Polynomial-Time Reduction การศึกษาปัญหาตัวอย่างช่วยให้เข้าใจแนวคิดการตรวจสอบคำตอบ การค้นหาคำตอบ และการพิสูจน์ความยากได้ชัดเจนยิ่งขึ้น

9.1 Boolean Satisfiability Problem (SAT)

SAT หรือปัญหาความเป็นจริงของสูตรตรรกศาสตร์แบบบูลีน เป็นปัญหาที่ถามว่าสามารถกำหนดค่าความจริงให้ตัวแปรต่าง ๆ เพื่อให้สูตรตรรกศาสตร์ทั้งหมดเป็นจริงได้หรือไม่ ตัวแปรแต่ละตัวสามารถมีค่า True หรือ False และสูตรสามารถประกอบด้วยตัวดำเนินการ เช่น AND, OR และ NOT

ตัวอย่างเช่น F = (x ∨ y) ∧ (¬x ∨ z)

หากกำหนด x = True, y = False และ z = True จะได้ว่า Clause แรกเป็นจริงเพราะ x เป็นจริง และ Clause ที่สองเป็นจริงเพราะ z เป็นจริง ดังนั้นสูตรทั้งหมดจึงเป็นจริง

SAT เป็นปัญหาที่อยู่ใน NP เพราะหากมีชุดค่าความจริงมาให้ เราสามารถตรวจสอบสูตรได้ในเวลาพหุนาม ปัญหานี้ยังเป็น NP-Complete ตามทฤษฎีบท Cook–Levin ซึ่งเป็นรากฐานสำคัญของการศึกษา NP-Completeness

9.2 3-SAT

3-SAT เป็นปัญหาย่อยของ SAT ที่สูตรอยู่ในรูป Conjunctive Normal Form หรือ CNF โดยแต่ละ Clause มีตัวแปรหรือตัวแปรปฏิเสธไม่เกินสามตัวตามนิยามที่ใช้ในทฤษฎีความซับซ้อน

ตัวอย่างสูตร 3-SAT ได้แก่ F = (x ∨ y ∨ z) ∧ (¬x ∨ y ∨ w)

คำถามคือสามารถกำหนดค่าความจริงให้ x, y, z, w เพื่อให้ทุก Clause เป็นจริงพร้อมกันได้หรือไม่ หากกำหนดค่าตัวแปรให้เหมาะสม เราสามารถตรวจสอบสูตรได้โดยประเมินแต่ละ Clause และรวมผลลัพธ์ด้วย AND

3-SAT เป็น NP-Complete และมีบทบาทสำคัญในการพิสูจน์ความยากของปัญหาอื่น เนื่องจากสามารถสร้างโครงสร้างทางตรรกศาสตร์เพื่อแปลงไปเป็นปัญหาในรูปแบบกราฟหรือปัญหาการจัดสรรได้

9.3 Vertex Cover

Vertex Cover เป็นปัญหาเกี่ยวกับกราฟที่ต้องการเลือกชุดจุดยอดให้ครอบคลุมเส้นเชื่อมทุกเส้น กล่าวคือ ทุกเส้นเชื่อมจะต้องมีปลายอย่างน้อยหนึ่งด้านอยู่ในชุดจุดยอดที่เลือก

สำหรับ Vertex Cover แบบ Decision จะถามว่ามี Vertex Cover ที่มีขนาดไม่เกิน k หรือไม่ ตัวอย่างเช่น กราฟที่มีจุดยอด A, B, C และมีเส้นเชื่อม A–B กับ B–C สามารถใช้ชุด {B} ครอบคลุมเส้นเชื่อมทั้งสองเส้นได้ ดังนั้นหาก k = 1 คำตอบคือ Yes

Vertex Cover แบบ Decision เป็น NP-Complete เพราะสามารถตรวจสอบชุดจุดยอดที่เสนอมาได้ในเวลาพหุนาม และปัญหานี้มีความยากตามนิยาม NP-Hard ด้วย

9.4 Hamiltonian Cycle

Hamiltonian Cycle เป็นปัญหาที่ถามว่ากราฟมีวงจรที่ผ่านจุดยอดทุกจุดเพียงครั้งเดียวก่อนกลับมายังจุดเริ่มต้นหรือไม่ ปัญหานี้แตกต่างจากการหาเส้นทางสั้นที่สุด เพราะไม่ได้พิจารณาว่าน้ำหนักรวมของเส้นเชื่อมต่ำที่สุดหรือไม่ แต่เน้นว่ามีวงจรที่ผ่านทุกจุดยอดครบตามเงื่อนไขหรือไม่

ตัวอย่างเช่น หากกราฟมีจุดยอด A, B, C และ D และมีเส้นเชื่อม A–B, B–C, C–D และ D–A จะได้วงจร A–B–C–D–A ซึ่งผ่านจุดยอดทุกจุดครั้งเดียวก่อนกลับมายังจุดเริ่มต้น ดังนั้นกราฟนี้มี Hamiltonian Cycle

Hamiltonian Cycle เป็น NP-Complete สำหรับกราฟทั่วไป เพราะสามารถตรวจสอบวงจรที่เสนอมาให้ได้ในเวลาพหุนาม และปัญหานี้เป็น NP-Hard ด้วย

9.5 Traveling Salesman Problem แบบ Decision Version

Traveling Salesman Problem หรือ TSP เป็นปัญหาการหาเส้นทางสำหรับพนักงานขายที่ต้องเดินทางไปยังเมืองทุกเมืองและกลับมายังเมืองเริ่มต้น โดยต้องการให้ระยะทางรวมต่ำที่สุด

ในรูปแบบ Optimization คำถามคือเส้นทางใดมีระยะทางรวมน้อยที่สุด ส่วน Decision Version จะเปลี่ยนเป็นคำถามว่า มีเส้นทางที่เดินทางผ่านทุกเมืองและกลับมายังเมืองเริ่มต้นโดยมีระยะทางรวมไม่เกินค่า B หรือไม่

ตัวอย่างเช่น มีเมือง A, B และ C โดยระยะทาง A–B เท่ากับ 2 กิโลเมตร B–C เท่ากับ 3 กิโลเมตร และ C–A เท่ากับ 4 กิโลเมตร หากกำหนดขอบเขต B = 9 เส้นทาง A–B–C–A มีระยะทางรวม 9 กิโลเมตรพอดี ดังนั้นคำตอบของรุ่น Decision คือ Yes

TSP แบบ Decision อยู่ใน NP เพราะสามารถตรวจสอบลำดับเมืองและคำนวณระยะทางรวมได้ในเวลาพหุนาม และเป็น NP-Complete ภายใต้รูปแบบมาตรฐาน ส่วน TSP แบบ Optimization เป็น NP-Hard

9.6 การเปรียบเทียบปัญหาทั้งห้า

ปัญหา สิ่งที่ต้องการตรวจสอบ Certificate ตัวอย่าง
SAT สูตรตรรกศาสตร์ทำให้เป็นจริงได้หรือไม่ ชุดค่าความจริง
3-SAT สูตร 3-CNF ทำให้เป็นจริงได้หรือไม่ ชุดค่าความจริง
Vertex Cover มีชุดจุดยอดขนาดไม่เกิน k หรือไม่ ชุดจุดยอด
Hamiltonian Cycle มีวงจรผ่านทุกจุดยอดครบหรือไม่ ลำดับจุดยอด
TSP แบบ Decision มีเส้นทางวงรอบที่มีระยะทางไม่เกิน B หรือไม่ ลำดับเมือง

9.7 สรุป

SAT, 3-SAT, Vertex Cover, Hamiltonian Cycle และ TSP แบบ Decision เป็นตัวอย่างสำคัญของปัญหา NP-Complete ปัญหาเหล่านี้มีลักษณะแตกต่างกัน แต่มีคุณสมบัติร่วมกันคือสามารถตรวจสอบ Certificate ของคำตอบแบบ Yes ได้ในเวลาพหุนาม และมีความยากตามนิยาม NP-Hard การศึกษาปัญหาเหล่านี้ช่วยให้เข้าใจการลดรูปและการพิสูจน์ความซับซ้อนของปัญหาอื่น ๆ ได้ดีขึ้น

10Approaches to Solving NP-Hard Problems

แนวทาง แนวคิด ตัวอย่างใช้งาน
Brute Force ลองทุกคำตอบ ได้ค่าที่ดีที่สุดแน่นอน แต่ช้า TSP 15 เมือง = 14!/2 ≈ 4.4×10¹⁰ เส้นทาง ใช้ได้กับข้อมูลเล็ก
Approximation เร็ว และรับประกันว่าคำตอบไม่แย่กว่าค่าที่ดีที่สุดเกินอัตราที่กำหนด Vertex Cover: เลือกเส้นที่ยังไม่ถูกครอบ ใส่ปลายทั้งสองด้าน ได้ ≤ 2 เท่าของค่าที่ดีที่สุด
Heuristics ใช้กฎเชิงปฏิบัติ เร็วแต่ไม่รับประกันคุณภาพ TSP แบบ Nearest Neighbor (ไปเมืองใกล้สุดที่ยังไม่ผ่าน)
Metaheuristics กรอบค้นหาทั่วไป เช่น Genetic Algorithm, Simulated Annealing, Tabu Search จัดตารางงาน, จัดเส้นทางรถขนส่ง

สรุปความรู้ที่ได้รับ

  • P: แก้ได้ใน poly แบบ Deterministic
  • NP: ตรวจคำตอบ Yes ด้วย Certificate ได้ใน poly
  • NP-Hard: ยากอย่างน้อยเท่าทุกปัญหาใน NP (ภายใต้ ≤ₚ)
  • NP-Complete: อยู่ใน NP และเป็น NP-Hard (พิสูจน์ต้องแสดงทั้งสอง)
  • P ⊆ NP แต่ P = NP ยังเป็นปัญหาเปิด; ในทางปฏิบัติเลือกวิธีให้เหมาะกับขนาดปัญหา

ขยายความ (เนื้อหาละเอียด)

10.1 ปัญหาในการแก้ NP-Hard

ปัญหา NP-Hard เป็นปัญหาที่มีความยากอย่างน้อยเทียบเท่ากับทุกปัญหาใน NP ภายใต้ Polynomial-Time Reduction สำหรับปัญหา Optimization หลายประเภท ยังไม่มีอัลกอริทึมที่ทราบว่าสามารถหาคำตอบที่ดีที่สุดได้ในเวลาพหุนามสำหรับทุกกรณี หาก P ≠ NP ก็ไม่สามารถมีอัลกอริทึมพหุนามสำหรับปัญหา NP-Complete ได้

อย่างไรก็ตาม การไม่มีอัลกอริทึมพหุนามที่ทราบในปัจจุบันไม่ได้หมายความว่าเราไม่สามารถแก้ปัญหาเหล่านี้ได้เลย นักวิจัยจึงพัฒนาวิธีการหลายแบบเพื่อหาคำตอบที่ดีที่สุดในกรณีขนาดเล็ก หรือหาคำตอบที่ดีและใช้งานได้จริงในกรณีขนาดใหญ่

แนวทางสำคัญ ได้แก่ Brute Force, Approximation Algorithms, Heuristics และ Metaheuristics โดยแต่ละวิธีมีจุดเด่นและข้อจำกัดแตกต่างกัน

10.2 Brute Force

Brute Force เป็นวิธีแก้ปัญหาที่พิจารณาคำตอบหรือทางเลือกที่เป็นไปได้ทั้งหมด แล้วเปรียบเทียบผลลัพธ์เพื่อหาคำตอบที่ตรงกับเงื่อนไขหรือดีที่สุด วิธีนี้มีข้อดีคือเข้าใจง่าย และหากตรวจสอบครบทุกกรณีอย่างถูกต้อง ก็สามารถรับประกันได้ว่าจะพบคำตอบที่ดีที่สุดเมื่อปัญหามีคำตอบและการค้นหาครอบคลุมทุกกรณี

ตัวอย่างเช่น ใน Traveling Salesman Problem เราอาจสร้างลำดับการเดินทางทุกแบบ คำนวณระยะทางรวมของแต่ละเส้นทาง แล้วเลือกเส้นทางที่มีระยะทางน้อยที่สุด วิธีนี้ให้คำตอบที่ดีที่สุด แต่จำนวนเส้นทางเพิ่มขึ้นอย่างรวดเร็วตามจำนวนเมือง โดยอาจเติบโตในระดับแฟกทอเรียล

ข้อจำกัดสำคัญคือ Brute Force ไม่เหมาะกับปัญหาขนาดใหญ่ เนื่องจากจำนวนทางเลือกอาจมีมากจนใช้เวลานานเกินไป อย่างไรก็ตาม วิธีนี้ยังมีประโยชน์กับข้อมูลขนาดเล็ก ใช้ตรวจสอบคำตอบของอัลกอริทึมอื่น หรือใช้เป็นวิธีอ้างอิงในการทดลองประสิทธิภาพ

10.3 Approximation Algorithms

Approximation Algorithms หรืออัลกอริทึมประมาณค่า เป็นวิธีที่ออกแบบมาเพื่อหาคำตอบที่ดีในเวลาที่มีประสิทธิภาพ โดยไม่จำเป็นต้องได้คำตอบที่ดีที่สุดเสมอไป จุดเด่นของวิธีนี้คือ ในปัญหาที่มีเงื่อนไขเหมาะสม สามารถพิสูจน์ขอบเขตคุณภาพของคำตอบที่ได้เมื่อเทียบกับคำตอบที่ดีที่สุด

ตัวอย่างเช่น ในปัญหา Vertex Cover มีอัลกอริทึมประมาณค่าที่ให้คำตอบมีขนาดไม่เกินสองเท่าของคำตอบที่ดีที่สุดสำหรับกราฟทั่วไป โดยใช้แนวคิดการเลือกเส้นเชื่อมที่ยังไม่ถูกครอบคลุม แล้วเลือกจุดยอดปลายทั้งสองด้านของเส้นเชื่อมนั้นเข้าชุดคำตอบ จากนั้นทำซ้ำกับเส้นเชื่อมที่ยังเหลือและไม่ติดกับเส้นเชื่อมที่เลือกไว้

อีกตัวอย่างหนึ่งคือปัญหา Set Cover ซึ่งต้องการเลือกชุดย่อยจำนวนต่ำที่สุดให้ครอบคลุมองค์ประกอบทั้งหมด อัลกอริทึมแบบ Greedy สามารถเลือกชุดที่ครอบคลุมองค์ประกอบที่ยังไม่ถูกครอบคลุมได้มากที่สุดในแต่ละขั้นตอน วิธีนี้มีขอบเขตคุณภาพที่วิเคราะห์ได้ แม้ไม่รับประกันว่าจะได้คำตอบที่ดีที่สุดเสมอไป

Approximation Algorithms มีประโยชน์เมื่อผู้ใช้ต้องการคำตอบที่มีคุณภาพและต้องการหลักประกันทางคณิตศาสตร์เกี่ยวกับความคลาดเคลื่อนจากคำตอบที่ดีที่สุด ทั้งนี้ไม่ใช่ทุกปัญหา NP-Hard จะมีอัลกอริทึมประมาณค่าที่มีคุณสมบัติที่ต้องการได้ง่าย และบางปัญหาอาจมีข้อจำกัดในการประมาณค่าอย่างเข้มงวด

10.4 Heuristics

Heuristics หรือวิธีฮิวริสติก เป็นวิธีแก้ปัญหาที่ใช้กฎ ประสบการณ์ หรือแนวทางที่ช่วยลดจำนวนการค้นหา เพื่อให้ได้คำตอบที่ดีในเวลาจำกัด วิธีนี้ไม่จำเป็นต้องมีหลักประกันทางคณิตศาสตร์ว่าคำตอบจะใกล้เคียงกับคำตอบที่ดีที่สุดเพียงใด

ตัวอย่างเช่น ในปัญหา Traveling Salesman Problem อาจใช้วิธี Nearest Neighbor โดยเริ่มจากเมืองหนึ่ง แล้วเดินทางไปยังเมืองที่ยังไม่เคยเยี่ยมชมและอยู่ใกล้ที่สุด ทำซ้ำจนผ่านทุกเมือง จากนั้นจึงกลับไปยังเมืองเริ่มต้น

วิธี Nearest Neighbor เข้าใจง่ายและทำงานได้รวดเร็วเมื่อเทียบกับการตรวจสอบทุกเส้นทาง แต่เส้นทางที่ได้อาจไม่ใช่เส้นทางที่ดีที่สุด และบางกรณีอาจมีระยะทางรวมสูงกว่าคำตอบที่ดีที่สุดมาก

ข้อดีของ Heuristics คือสามารถออกแบบให้เหมาะกับปัญหาเฉพาะด้านได้ เช่น การจัดตารางเรียน การวางแผนการผลิต การจัดเส้นทางขนส่ง และการจัดสรรทรัพยากร ข้อเสียคือคุณภาพของคำตอบขึ้นอยู่กับกฎที่ออกแบบและลักษณะของข้อมูล

10.5 Metaheuristics

Metaheuristics เป็นกรอบวิธีค้นหาคำตอบระดับสูงที่ใช้แนวคิดการสำรวจและปรับปรุงคำตอบ เพื่อค้นหาคำตอบที่ดีในพื้นที่ค้นหาขนาดใหญ่ วิธีเหล่านี้มักใช้ร่วมกับ Heuristics และไม่ได้รับประกันว่าจะพบคำตอบที่ดีที่สุดในทุกกรณี แต่มีประโยชน์กับปัญหา Optimization ที่ซับซ้อน

ตัวอย่างวิธี Metaheuristics ได้แก่

Genetic Algorithm ใช้แนวคิดที่คล้ายกับวิวัฒนาการ โดยสร้างกลุ่มคำตอบหลายชุด แล้วคัดเลือกคำตอบที่มีคุณภาพมาสร้างคำตอบรุ่นใหม่ผ่านกระบวนการ เช่น Crossover และ Mutation วิธีนี้อาจใช้กับการจัดเส้นทาง การจัดตารางงาน และการออกแบบระบบ

Simulated Annealing ใช้แนวคิดจากการอบและทำให้วัสดุเย็นลง โดยเริ่มจากคำตอบหนึ่งแล้วสุ่มเปลี่ยนคำตอบเป็นคำตอบข้างเคียง บางครั้งอาจยอมรับคำตอบที่แย่ลงเพื่อช่วยหลีกเลี่ยงการติดอยู่ในคำตอบเฉพาะที่ และค่อย ๆ ลดโอกาสยอมรับคำตอบที่แย่ลงเมื่อกระบวนการดำเนินต่อไป

Tabu Search เป็นวิธีค้นหาที่ใช้รายการ Tabu เพื่อป้องกันการย้อนกลับไปยังคำตอบหรือการเคลื่อนไหวบางอย่างที่เพิ่งใช้ ช่วยลดการวนซ้ำและส่งเสริมการสำรวจพื้นที่ค้นหาใหม่

Metaheuristics มีประโยชน์ในปัญหาที่มีตัวแปรและข้อจำกัดจำนวนมาก เช่น การวางแผนการผลิต การจัดตารางพนักงาน และการวางเส้นทางรถขนส่ง อย่างไรก็ตาม ผลลัพธ์อาจขึ้นอยู่กับการตั้งค่าพารามิเตอร์ วิธีแทนคำตอบ และเงื่อนไขหยุดการค้นหา

10.6 การเปรียบเทียบแนวทางแก้ปัญหา

วิธี จุดเด่น ข้อจำกัด
Brute Force หาคำตอบดีที่สุดได้หากตรวจสอบครบทุกกรณี ใช้เวลาสูงเมื่อข้อมูลใหญ่
Approximation มีขอบเขตคุณภาพคำตอบในปัญหาที่เหมาะสม อาจไม่พบคำตอบดีที่สุด
Heuristics เรียบง่ายและออกแบบเฉพาะปัญหาได้ ไม่มีหลักประกันคุณภาพทั่วไป
Metaheuristics สำรวจพื้นที่ค้นหาขนาดใหญ่ได้ ผลลัพธ์ขึ้นกับวิธีและพารามิเตอร์

10.7 ตัวอย่างการประยุกต์ใช้จริง

ในระบบขนส่งสินค้า บริษัทอาจต้องกำหนดเส้นทางรถให้ผ่านลูกค้าหลายรายโดยลดระยะทางรวมและต้นทุนเชื้อเพลิง การใช้ Brute Force อาจเหมาะกับจำนวนจุดส่งน้อย แต่ไม่เหมาะกับการส่งสินค้าหลายร้อยจุด

บริษัทจึงอาจใช้ Approximation Algorithm เพื่อให้ได้คำตอบที่มีขอบเขตคุณภาพ หรือใช้ Heuristics เพื่อค้นหาเส้นทางที่ดีอย่างรวดเร็ว หากปัญหามีข้อจำกัดจำนวนมาก อาจใช้ Metaheuristics เช่น Genetic Algorithm เพื่อปรับปรุงเส้นทางหลายรอบและเลือกคำตอบที่เหมาะสมกับเป้าหมายของระบบ

ตัวอย่างนี้แสดงให้เห็นว่า การแก้ปัญหา NP-Hard ในทางปฏิบัติไม่ได้มีวิธีเดียว แต่ต้องเลือกเทคนิคให้เหมาะกับขนาดปัญหา เวลา งบประมาณ และคุณภาพคำตอบที่ต้องการ

10.8 สรุปความรู้ที่ได้รับจากการศึกษา

จากการศึกษาทฤษฎีความซับซ้อนในการคำนวณ ทำให้เข้าใจว่าปัญหาคอมพิวเตอร์มีระดับความยากแตกต่างกัน และไม่ใช่ทุกปัญหาจะมีวิธีแก้ที่มีประสิทธิภาพเท่ากัน Class P ประกอบด้วยปัญหาที่แก้ได้ในเวลาพหุนาม ส่วน Class NP ประกอบด้วยปัญหาที่ตรวจสอบ Certificate ของคำตอบแบบ Yes ได้ในเวลาพหุนาม NP-Hard ใช้แสดงความยากที่อย่างน้อยเทียบเท่าปัญหาทุกปัญหาใน NP และ NP-Complete เป็นปัญหาที่อยู่ใน NP พร้อมทั้งเป็น NP-Hard ด้วย

นอกจากนี้ Polynomial-Time Reduction ยังเป็นเครื่องมือสำคัญในการพิสูจน์ความยากของปัญหา โดยแปลงปัญหาที่ทราบสถานะแล้วไปยังปัญหาที่ต้องการศึกษา ส่วนการแก้ปัญหา NP-Hard ในทางปฏิบัติอาจต้องเลือกใช้ Brute Force, Approximation Algorithms, Heuristics หรือ Metaheuristics ให้เหมาะสมกับสถานการณ์

โดยสรุป Computational Complexity Theory ไม่เพียงช่วยจำแนกปัญหาทางคอมพิวเตอร์ แต่ยังช่วยให้นักพัฒนาตัดสินใจได้อย่างมีเหตุผลว่าจะค้นหาคำตอบที่ดีที่สุด ใช้วิธีประมาณค่า หรือออกแบบวิธีค้นหาเฉพาะสำหรับปัญหานั้นอย่างไร
